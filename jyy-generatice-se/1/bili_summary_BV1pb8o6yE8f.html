01

课程简介

00:00 – 29:44　·　10 小节　·　官方章节名原样

这一章只做三件事：交代这门课为什么存在（AI 把「昂贵的能力」变成了日用品，于是「上大学」这件事本身需要重新论证），交代这门课怎么上（案例为主、松散组织、允许不来上课），以及从零科普大语言模型与 agent。这一讲没有技术门槛，但讲师抛出的问题很重：如果所有人的简历都长一个样，你凭什么被招？

1.1站在人类命运的交叉路口：把昂贵的能力变成日用品

回跳 0:00

讲师用他自己的 Neovim 开场：按 F5，打开浏览器，开课。然后给出这门课的定位——不是「教编程」，而是站在计算机发展史的一个转折点上，回头看每次技术变革真正改变了什么。

他给出的归纳只有一句：每一次变革，都是把昂贵的能力变成了日用品。

1.2两份焦虑：一份怕被取代，一份怕白学

回跳 3:00

讲师把学生的焦虑拆成两种，而且很明确地说这两种焦虑指向相反的方向——一种是因为太依赖 AI，一种是因为太听老师的话。

第一种焦虑
如果每门课都开卷考试、都让 AI 答题，我全都答对了；但出来以后，第一个被 AI 取代的就是我。
第二种焦虑
延续中学状态、老师说啥就做啥、每堂课都认真听、每次作业都认真做。四年毕业时发现——你确实学会了一点什么，但你学会的东西 AI 都会做。
最切实的痛苦
保研。投了很多简历，海投很多地方。

「我其实也收到了很多这样的简历，我觉得很糟糕。因为所有这一切都是 AI 做的，我没有干任何事，我就告诉它有一份简历。」

—— 讲师，约 4:40
值得记的观察
  • 两种焦虑看起来矛盾，其实同源：都指向「你的产出无法与别人的产出区分」。依赖 AI 的人和不用 AI 的人，交出来的东西在形式上是一样的。
  • 讲师把课程目标直接对准这个痛处：「我希望用这一门课来缓解一下大家这样的焦虑的情绪，更多的是带着大家觉得还原一种快乐 vibecoding 的快乐。」

1.3为什么一份「堆满成果」的简历是零分的

回跳 4:50

讲师现场投屏了一份真实简历（个人信息已替换为 Unicode 方块）。看起来很漂亮：CCF 期刊列表、论文、accepted。他的判断是——这是零分的简历。

这一节的结论
  • 简历的判分标准不是「成果数量」，而是能否从中还原出「你个人做了什么」。
  • 讲师明确说：「那你应该怎么样向你的未来的导师去展示你自己？」——这是这门课整个学期的暗线。

1.4人的两个优势：信息差，以及「你可以坐牢」

回跳 8:10

讲师自问自答：软件工程是干什么的？「很简单，怎么样让软件工程不失败——怎么样造出一个软件来。」那么在 AI 比你会做题之后，「人」剩下的优势是什么？他给了两条，第二条带点玩笑但意思很实在。

1.5这门课怎么上：把上课做成一场可回放的表演

回跳 10:20

这是本章信息密度最高的一段：讲师把自己的备课流程完整地展示了一遍，而且这套流程本身就是这门课的第一个案例。

讲师的幻灯片生产流水线
  1. 课前先写讲义（Markdown）——「相当于我会先想好我今天上课的时候我大概在这个时间应该讲什么、举什么样的例子，相当于我要约束好 AI 做什么。」
  2. 按 F5 播放时，Markdown 会渲染成 slides。紫色部分是 GPT-5.6s「添油加醋」加上去的，他自己的内容与 AI 生成的内容在视觉上可区分。
  3. 调用一个叫 make slides 的 skill，从一个写好的 Markdown 生成整套 slides。
  4. 其中还有一个「AI 梗同学」的 skill：生成三个 subagent 并赋予不同的 personality，各自在隔离的上下文里干活，最后主 agent 回来汇总。
  5. 换了几版提示词，每一版都重新生成一次；最后用一个别的模型盲评，挑出质量最高的一版。
讲师的自我定位

「我认为如果你是来学习的那更高效的方法——比如说我做一个老师，我应该思考的是怎么样把知识以更好的方式呈现给大家，而我的答案是我应该在上课的时候，上课是一种表演。」所以他自称演员：调动情绪、按预设剧本演出、课后 review 表演。

1.6三条课程政策：禁止古法编程、token 自费、通过/不通过

回跳 14:00

三条政策里，最有信息量的不是「禁止古法编程」，而是他对「为什么用便宜模型」的解释——这直接说明了他对当前模型能力的判断。

政策内容讲师给的理由（原话要点）
禁止古法编程 不许手搓。课程要求用 agent 完成。 「你们各个都是古法编程的好手，因为你们要考试、要保研、要机试。」他知道这个体系短期内改不了：「你要改变一个体系很难，但是我非常想要撕开一个小的口子。」
token 自费 自己充 token。他会用便宜的模型上课。 「如果你们手上没有付费的 token，就应该立即退学。」课上所有演示——包括 slides 生成、所有 assets——全部用 DeepSeek V4 Flash，只有 slides 生成用「更聪明的模型」。理由：证明「一个足够便宜但智能相对有一些的模型」就能带大家做完这些事。
通过 / 不通过 考核方式只有两档。 「在这个时代分数已经变得不那么重要了，而真正重要的就是在你最后找工作、或者在你保研的那一刻，投去那个简历上面有什么东西。」课的产出建议：实现一个自己的 email 管理系统，跑在宿舍一台常开的小电脑上。
值得记的细节
  • 关于 token 的价值，讲师说了一句很直白的话：「你没有 token 你就可以立即退休了」——后面第 2 章他会用自己「一句话装 Linux」来证明这句不是夸张。
  • 他提到学生「喜欢在夜里工作」，而 DeepSeek 夜间计价更便宜，于是有了那个「梁文峰时间 / 梁文谷时间」的梗（保留在页脚修正表里）。
  • 他明说无法限制学生用什么模型：「同一个任务你让 Claude 来做就是比 DeepSeek V4 Flash 做得又好又快，没办法。」这是他对「分数不可比」的解释。
  • 关于课程的终极想象，他说得有点吓人：如果每个人的电脑都装监控，AI 就能评判你大学四年是怎么过的——「这是一个非常非常恐怖的事情」。他的态度是「保持 open」。

1.7大语言模型是什么：一个学到的概率分布，仅此而已

回跳 18:00

讲师明确说了「我今天不讲什么是大语言模型」，然后给了最短的定义——它就是一个概率分布，和你概率统计课上抛硬币的题没有任何区别。

本节的极简定义

「大语言模型就是一个概率分布，跟你们在概率统计课上学的抛硬币……没有任何的区别。它是一个学到的概率分布。」

1.8从 GPT-4 到 GPT-5.6：同一件事，从「调半天」到「一句话」

回跳 21:30

讲师用两个自己的真实经历做对照，时间跨度只有一两年，但工作量的差别是数量级的。

1.9agent 是怎么出现的：一个特殊 token 换来越来越强的自主性

回跳 23:10

讲师现场展示了他自己的环境配置（Sway 窗口管理器 + 定制终端），并且强调这些配置他一行都没手写过——只用了一个 prompt。

1.10故事还没结束：摩尔定律还在，但路线未定

回跳 27:40

本章最后一段是纯判断，没有事实可核对——但它是理解全课基调的前提，所以值得原样记下来。

讲师对未来的判断
  • 「agent 的能力还远远没有被释放出来。」
  • next-token prediction「是一个效率很低的模型」，未来可能有 diffusion 型的语言模型——「从一个随机的噪声开始，一点一点生成了一个很长的东西，像人做梦一样」。
  • 「我不是 predict next token，我可以把上下文回头去改，随时可以把一个很长的上下文裁短。」
  • 「整个 AI research 大家都在赌这件事情要发生，摩尔定律还在那。我现在很难想未来会变成什么，我不能预测未来到底哪一条路线会胜出。」

「你可以预见的是，这个世界肯定会变得非常的不一样。那在这个世界上我们应该怎么办，是每一个同学我觉得都值得好好考虑一下的问题。」

—— 第 01 章收束，约 29:00

2.1用 agent 的两个原则：现在就用，以及随时问他

回跳 29:44

讲师先坦白自己的假设前提：「我先假设大家其实不会用 agent——不太会用 agent，就除了什么『把我把这个作业做了』以外。」然后给出两个他已经用了一学期的原则。

原则一 · 现在就开始用

  3. 并且可以写配置文件，比如 AGENTS.md。

他现场演示了配置文件的威力：问 agent「你是谁」，它回答自己是「生成式软件工程的助教 agent」。讲师接着追问——「你不就是个模型吗，为什么还知道生成式软件工程？」

讲师留的课后作业

「正好一会儿课间的时候大家可以想一想：你用 agent 做的最酷的一件事情是什么？想象力是你们的上限。」

2.6用 agent 读 B 站视频：效率差距是十倍一百倍，但有个前提

回跳 45:20

这是本章最后一个例子，也是和本笔记自身最相关的一个。讲师说明了他的「读视频」流程，并且给出了一句警告。

讲师读一个视频的流程
  1. 给一个 BVID。
  2. 「一般来说我会读什么呢？就读这个 podcast。」——优先选长对话/访谈类内容。
  3. 把它总结成一个自动的图文时间轴。「你看这是整理过的，这个文本的质量还是可以的，比字幕的质量要高一些。」
  4. 关键在于截图密度：「实际上我的截图的密度会更大一些。当我两帧图片之间的间隔大到一定程度的时候，我就会解读，我就得到了这个视频说的 ground truth。」
  5. 然后「AI 梗同学」上线消化：「因为它有我的记忆，把我认为不需要看、trivial 的东西——比如说这里面所有东西都是我非常清楚的东西，那么我就不需要看它。」
  6. 结果：「我就可以在几分钟的时间里面看完一个一两个小时的视频，而且我基本上确信，我还是很好地知道了那里面不一样的东西。」
前提条件（他没省略）

「那当然剥夺了你们娱乐的——如果你是这样娱乐，看一个什么滑翔买瓜的衍生视频，那就不要用 AI 读了。」

视频恢复—实操 (2)：浏览器是最好的入口

48:34 – 65:10　·　6 小节

本章由一个真实的直播事故开场——USB 采集卡断了，讲师当场让 agent 修。接着他把视角从「单个 agent 能做什么」升到「生态能做什么」，核心论点是：浏览器是人类软件工程的奇迹之一，而 Chrome DevTools 是给开发者留的那个口子；普通人以前进不去，现在进得去了。这一章有全片最完整的一次「现场翻车 + 收敛」演示。

3.1直播事故：agent 用软件把 USB 拔了又插回去

回跳 48:34

这是全片最好的案例，因为它是计划外的、真实的、有物理约束的问题：教室的视频采集卡通过 USB 接入，中途断了；而接口在机器后面，讲师碰不到。

回到「普通人」的主线

3.4现场翻车：让 AI 去填教务系统，它一开始不听指令

回跳 55:30

这是全片最有价值的一段，因为它展示了真实的失败过程，而不是剪好的成功案例。任务是：填教学周历（讲师非常讨厌填这个）。

翻车点 1 · 不听指令

讲师说：「帮我用随便什么 AI 填写，不要看任何东西。」因为如果不加这句，agent 会去读他目录里的 ripple 之类的其他文件。结果——「你看他还在干这个事，对吧，我就是想让他去填。你看他他就是不听指令。」

讲师把原因归给了模型选择：「这是 DeepSeek V4 Flash 的问题。如果是最一线的模型它会知道。翻车也是经常有的，所以模型其实还在不断的能力增长中。」

3.5从一次成功到自动抢课脚本：能力真正的边界在哪里

回跳 58:20

三连推论（讲师原话）
  • 「当它走通过一次以后，这个 session 里面的东西会留下来。」
  • 「我可以把它沉淀成确定性的脚本，对吧，它可以形成记忆——就是说这条路径应该怎么走、什么能成功、什么能失败。」
  • 「它也可以把走过的这些网页成功变成脚本，你就得到了一个自动选课抢课的系统。」
本章的技术结论

浏览器之所以是最好的入口，是因为它同时提供了三样东西：① 一个几乎覆盖所有日常事务的操作面（教务、邮箱、网盘、后台）；② DevTools 这个给开发者的完整观测/操作接口；③ 网页操作天然可验证（填进去了没、页面变没变）。

实操 (3)：Computer Science 从业者的视角

65:10 – 74:40　·　4 小节

上一章是「普通人怎么用」，这一章换视角：CS 从业者知道边界在哪里。讲师用两个自己的项目说明这种区别——一个是把 140 份试卷的统分做成流水线（他知道什么时候不该让大模型做加法），另一个是「在机器管控下把文件偷出来」的 Excel 二维码工程（他知道该用什么中间语言）。这一章的核心命题是：一般人的瓶颈是「不知道提出什么」，CS 人的瓶颈是「知道该以什么形式复用」。

4.1改卷统分：一条「不信任大模型做加法」的流水线

回跳 1:05:10

这是全片最能体现「CS 从业者视角」的案例。讲师先讲了过去是怎么做的，然后讲今年他改成什么样。

过去（他自嘲对学生太好）

「改完以后我要统分，那一般来说这个任务就是给助教的：助教你去把这个分加了。然后助教就掏出一个计算器，12 加 13 加 14 加 15 加 16，然后再仔细合一遍。」

为什么这条流水线的收敛快

讲师的解释是：他知道边界在哪里。加法交给确定性脚本、识别交给本地视觉模型、复核交给人。每一段都用它最擅长的东西，而且每一段的「对不对」都能立刻判定。这比让一个 agent 从「统分」到「出分」一把梭要快得多，因为后者没有中途的 verifier。

4.2「机器管控下偷数据」这道题：CS 人才能想到的问题

回跳 1:08:10

讲师说明这道题的来由：「前几天在一个星期左右的时间里，有一个我们在群里面突然闲聊，说机器被管控了很讨厌。」然后他完整地描述了约束条件。

为什么他特意挑这道题

因为它的解法完全依赖对计算机系统的理解：「你是 Computer Science 的学生，你知道你上过操作系统、上过计算机网络，你知道这里面需要的组件是什么，你就可以把这个 vibecoding 出来。」

4.3Excel 二维码是怎么做出来的：一次「先探路再放手」的实验

回跳 1:10:50

回跳 1:13:30

软件工程：三个空间，以及它们之间的 gap

74:40 – 100:00　·　7 小节

全片的落点。讲师先用「idea 都有了就差一个程序员」拆掉「AI 强 = 产品能成」的幻觉，再用 QR Gen 项目两次失败与一次成功做实证，最后给出这门课的核心理论框架：intention → specification → implementation 三个空间，软件工程的全部工作就是补这三者之间的 gap。结尾回到《人月神话》与教育体系。

5.1「idea 都有了，就差一个程序员」——这句话在 AI 时代仍然成立

回跳 1:14:40

讲师先承认 AI 很强（「不着急，AI 也不是完全完美的」是他上一段的过渡语），然后指出：产品是一个系统性的工程。

5.2QR Gen 的两次暴毙：AI 为什么上来就「扩大问题」

回跳 1:17:50

这是全片最重要的技术分析。同一个需求给了模型两次，两次都失败，而失败原因完全一样。

需求原文（讲师说「非常明确」）

「我要一个 QR Code 的 Excel，用 Excel 2019 兼容的公式，把输入的任意一个字符串先用 Base64 编码，然后转成 QR Code 动画。」

补充：一次「跑到死」的实验

讲师还提到另一个模型（DeepSeek V4 Pro）的表现：「他已经没有办法遵循指令了。」以及那次烧掉 6 小时、被 output 限制截断、思考 25 分钟的实验——这些数字本身说明：在没有 verifier 的情况下，长任务的成本是不可控的。

5.3正确解法：先设计一个中间语言，让每一块都可单独验证

回跳 1:21:00

这是全片技术含量最高的一段，也是「软件工程在人机协作里仍然必要」的最强证据。讲师说明了他实际用了几条 prompt 做到的这件事。

讲师的实际做法（原话梳理）
  1. 让模型先设计一个符号系统 / 中间语言：「我让它设计一个各种各样的 Python 类，就有点像编译器一样。」
  2. 这个中间语言同时面向两个后端：「这个东西既可以翻译成、既可以在 Python 里面直接执行，又可以翻译成 Excel。」
  3. 于是可以分开验证两侧的翻译：「我只需要验证的是我的每一个翻译都是正确的——到 Excel 翻译是正确的、到 Python 的结果是正确的。」
  4. 在 Python 世界里验证算法本身：「我可以在 Python 世界里面验证我的 Base64 编码算的对不对、我的二维码的每个像素算的对不对。」
  5. 再单独验证「每个东西和 Excel 公式翻译的正确性」。
  6. 「尽量容尽，最后一把头生成——就直接正确，代码非常的干净也不长。」
这个案例的结论

「所以回过头来看，GPT-5.6 或者 Claude 的 build Excel——我真的觉得 AI 还是很厉害的，无穷多的硬编码。」但代价是：「这两份代码我让他们把那个工作区从一个位置移动到另外一个位置，他都得修两个小时。」对比之下，讲师那版的「维护性远比（那个）——代码非常的干净」。

所以：「在今天你还需要生成式软件工程，需要这门课。」

5.7人月神话与结尾：古法编程已死，软件工程还没有

《人月神话》里那个比喻（讲师复述）

「这里有一个很经典的论断：如果一个团队已经开始、或者一个软件产品已经开始失败，你加进去更多的人只会让它变得更失败，不会变得更成功。」

最后一页（讲师原文）

「这个问题上 GPT-5.6 回答的还挺好的——虽然他做不到。他说：他能找到能值得解决的问题，把未知拆成便宜的实验，用证据让坏方向及时停下，并对长期结果负责。」

「这是一个好的回答。但是我发现其实我太太做不到，很有意思。好，我今天课就到这。」
