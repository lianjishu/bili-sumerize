2.1主流选项与「操作逻辑通用」

01:08 – 02:24

「首先我们需要选择一款适合自己的编程 Agent。」UP 主列出当前的主流选项，然后直接给出推荐。

主流选项
Codex 和 Claude Code
此外还有
OpenCode、Pi、Cursor 等等（UP 主原话就举了这三个）
推荐选择
Codex——「如果你没有特殊要求的话，建议直接选择 Codex」
理由
「它的功能相对来说比较完善，几乎没有明显的短板」

接着 UP 主解释了 Codex 的模型来源，这里有个容易被忽略的要点：Codex 不跟 GPT 模型强绑定。

Codex 的模型接入方式
  • 作为 OpenAI 旗下的产品，可以通过订阅 ChatGPT，在 Codex 里调用 GPT 模型。
  • 如果不方便订阅，也可以把 DeepSeek、GLM、Kimi 等国产模型接进来。
  • UP 主的判断：「Codex 算是一个通用的编程 Agent，它并不跟 GPT 模型强绑定，实际上大部分模型都能跟 Codex 配合使用。」
关于 UP 主自己的前置内容：他提到之前发过两期视频，分别讲 Codex 的基础用法、以及如何接入国产模型。那两期发布时间较早，当时 Codex 的界面跟现在「稍微有些区别」，但功能没有大的变化 —— 所以不影响本片。这两期不在本笔记范围内。
本片最重要的一句免责声明
  • 后续内容统一以 Codex 为例演示。
  • 但「我会尽量避免使用它独有的功能」——这里设计的核心操作逻辑都是通用的。
  • 也就是说，你用 Claude Code、Pi 或其它 Agent，同样可以完成本片的整个流程。

这一句是理解全片的前提：UP 主教的是一套与工具无关的协作流程（怎么对齐需求、怎么让 AI 能自测、什么时候该自己上手），而不是 Codex 的使用教程。工具会换，但这套流程不会。

「虽然演示用的是 Codex，但我会尽量避免使用它独有的功能。这里设计的核心操作逻辑都是通用的，你用 Claude Code、Pi 或者说是其他的 Agent，同样可以完成。」

—— UP 主原话（02:07 前后）
