### 踩坑：git push 静默失败 exit 128（根因＝`http_proxy` 环境变量）

**症状**：PowerShell 与 Bash 下 `git push` 都返回 **exit 128 且 stdout/stderr 全空**，
但 `git ls-remote`、`git credential fill`、带凭据的 `Invoke-WebRequest` 全部正常（HTTP 200）。
看起来像「凭据坏了」，其实是**代理**。

**根因链**（`GIT_CURL_VERBOSE=1` 挖出来的）：
1. 环境里有 `http_proxy=http://127.0.0.1:9982`（不止 `https_proxy`，`http_proxy` 也在）。
   git 默认走这个代理 → `Establish HTTP proxy tunnel` → `Connected to 127.0.0.1`。
2. 经代理访问 `git-receive-pack` 拿到 **401**，git 回头调 `git credential-manager get`，
   **进程在此处静默退出**（trace 最后一行就是 `run-command: 'git credential-manager get'`），
   凭据从没被回填重试 → 无任何报错输出，退出码 128。
3. 对照实验：`NO_PROXY=gitee.com` **无效**（git 仍走代理）；
   **必须把 `http_proxy` / `https_proxy` 一起删掉**才通。

**解法**（已验证成功）：
```powershell
Remove-Item Env:\http_proxy,Env:\https_proxy,Env:\HTTP_PROXY,Env:\HTTPS_PROXY -ErrorAction SilentlyContinue
```
或把 gitee 加进系统代理例外。推成功后 `git status -sb` 显示
`## main...origin/main`（无 ahead），origin/main = 8827a80。

**排查方法论**（值得复用）：git 报「静默 128 / 无输出」时，
`GIT_CURL_VERBOSE=1` + `GIT_TRACE=1` 重定向到文件是唯一能看见真相的手段；
再用 python `subprocess.run(capture_output=True)` 跑 git 能拿到**真实**退出码与纯净输出
（PowerShell 会把 git stderr 包成 `NativeCommandError` 且吞掉内容）。
